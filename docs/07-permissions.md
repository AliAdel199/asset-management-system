# مصفوفة الصلاحيات

هذه الوثيقة تحدد الصلاحيات المبدئية للأدوار في النسخة الأولى. الصلاحيات قابلة للتعديل بعد اعتماد الهيكل الإداري النهائي وأسماء الجهات المخولة.

## الأدوار الأولية

1. مسؤول النظام.
2. مستخدم مركزي.
3. مسؤول موجودات.
4. مسؤول صيانة.
5. مستخدم جهة.
6. مدقق أو قارئ تقارير.

## قواعد عامة للصلاحيات

1. كل مستخدم يرتبط بجهة تنظيمية.
2. مستخدم الجهة يشاهد بيانات جهته فقط.
3. المستخدم المركزي يشاهد المؤسسة الرئيسية والجهات التابعة حسب الصلاحيات.
4. العمليات المؤثرة تسجل في `AuditLog`.
5. لا يسمح بالحذف النهائي للموجودات لأي دور.
6. الشطب والنقل بين الجهات يحتاجان صلاحية مخولة.

## تفاصيل الأدوار

### مسؤول النظام

يمتلك أعلى صلاحيات تشغيلية لإعداد النظام، ولا يعني ذلك السماح بالحذف النهائي للموجودات.

صلاحياته:

1. إدارة المستخدمين.
2. إدارة الأدوار.
3. إدارة الهيكل الإداري.
4. عرض سجل العمليات.
5. إدارة البيانات المرجعية.

### مستخدم مركزي

يمثل مستخدمًا على مستوى المؤسسة الرئيسية أو جهة مخولة مركزيًا.

صلاحياته:

1. مشاهدة بيانات الجهات المصرح بها.
2. إدارة الموجودات ضمن نطاقه.
3. اعتماد النقل حسب التفويض.
4. تنفيذ أو اعتماد الشطب حسب التفويض.
5. اعتماد أو رفض طلبات الصيانة.
6. عرض التقارير المركزية.

### مسؤول موجودات

يدير سجل الموجودات وحركتها.

صلاحياته:

1. إضافة موجود.
2. تعديل بيانات موجود.
3. التسليم والاسترجاع.
4. طلب النقل.
5. رفع المرفقات.
6. عرض تاريخ الحركة.

### مسؤول صيانة

يدير طلبات الصيانة والمواد المصروفة.

صلاحياته:

1. إنشاء طلب صيانة.
2. اعتماد أو رفض طلبات الصيانة.
3. تعديل بيانات الصيانة.
4. إكمال الصيانة.
5. تسجيل المواد المصروفة.
6. رفع مرفقات الصيانة.

### مستخدم جهة

يمثل المستخدم العامل ضمن جهة محددة.

صلاحياته:

1. عرض موجودات جهته فقط.
2. طلب صيانة لموجودات جهته إذا اعتمدت المؤسسة ذلك.
3. طلب نقل أو استرجاع حسب التفويض.
4. عرض تقارير جهته.

### مدقق أو قارئ تقارير

يمثل مستخدمًا يحتاج القراءة والتدقيق دون تعديل.

صلاحياته:

1. عرض التقارير.
2. عرض سجل العمليات.
3. عرض تفاصيل الموجودات ضمن نطاقه.
4. لا يمتلك صلاحية تعديل أو شطب.

## صلاحيات تحتاج ضبطًا نهائيًا

1. تحديد الجهة المخولة باعتماد النقل.
2. تحديد الجهة المخولة باعتماد الشطب.
3. تحديد سياسة حذف أو إلغاء المرفقات الخاطئة.
4. تحديد هل تصدير التقارير يسجل دائمًا في `AuditLog`.

ملاحظة: البند الخاص بتحديد هل مستخدم الجهة ينشئ طلب صيانة مباشرة أم يرسل طلبًا فقط أصبح غير ذي موضوع - كل طلب صيانة يمر الآن بخطوة اعتماد إلزامية (نفس مبدأ النقل والشطب)، بصرف النظر عن الدور مقدّم الطلب.
