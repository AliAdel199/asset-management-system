# نموذج البيانات المفاهيمي

هذه الوثيقة تصف نموذج البيانات على مستوى مفاهيمي فقط. لا تمثل تصميم قاعدة بيانات نهائيًا، ولا تحتوي على Prisma Schema أو كود برمجي.

## مبادئ عامة

1. كل موجود يسجل كسجل مستقل في الكيان `Asset`.
2. كل موجود يمتلك رقمًا داخليًا فريدًا وفق الصيغة المعتمدة مبدئيًا `ORG-CAT-YYYY-SEQ`.
3. كل موجود يرتبط بتصنيف وجهة مالكة أو مستلمة وحالة تشغيلية.
4. الحركة لا تختزل داخل الحالة الحالية فقط، بل تحفظ في سجل مستقل.
5. الصيانة تحفظ كسجل مستقل مرتبط بموجود محدد.
6. المرفقات ترتبط بالموجود أو بإحدى عملياته مثل الصيانة أو النقل أو الشطب.
7. سجل العمليات يحفظ الأثر التدقيقي لكل عملية مؤثرة.

## الكيانات المفاهيمية

### OrganizationUnit

يمثل المؤسسة الرئيسية والجهات والمؤسسات والدوائر التابعة لها.

البيانات المفاهيمية:

1. اسم الجهة.
2. رمز الجهة.
3. نوع الجهة.
4. الجهة الأعلى.
5. حالة الجهة.

العلاقات:

1. الجهة قد تتبع جهة أعلى.
2. الجهة قد تضم مستخدمين.
3. الجهة قد تملك أو تستلم موجودات.

### User

يمثل مستخدم النظام.

البيانات المفاهيمية:

1. الاسم.
2. اسم الدخول.
3. الجهة المرتبط بها.
4. حالة المستخدم.
5. الدور أو الصلاحيات.

العلاقات:

1. المستخدم يرتبط بجهة واحدة أساسية.
2. المستخدم ينفذ عمليات تسجل في `AuditLog`.
3. المستخدم قد يرفع مرفقات.

### Role

يمثل دور المستخدم أو مجموعة صلاحياته.

البيانات المفاهيمية:

1. اسم الدور.
2. وصف الدور.
3. نطاق الصلاحية.
4. حالة الدور.

العلاقات:

1. الدور يمنح لمستخدم أو أكثر.
2. الدور يحدد العمليات المسموحة داخل الوحدات.

### AssetCategory

يمثل تصنيف الموجود.

البيانات المفاهيمية:

1. اسم التصنيف.
2. رمز التصنيف.
3. وصف التصنيف.
4. حالة التصنيف.

أمثلة:

1. أجهزة.
2. أثاث.
3. سيارات.
4. أراضٍ.
5. مبانٍ.

### AssetType

يمثل نوع المادة داخل التصنيف.

البيانات المفاهيمية:

1. اسم النوع.
2. التصنيف المرتبط.
3. وصف النوع.
4. حالة النوع.

أمثلة:

1. ميز.
2. ثلاجة.
3. حاسوب.
4. كاميرا.

### UsageNature

يمثل طبيعة استخدام الموجود.

البيانات المفاهيمية:

1. اسم طبيعة الاستخدام.
2. وصفها.
3. حالة السجل.

أمثلة:

1. طبية.
2. خدمية.

### Asset

يمثل السجل الرئيسي للموجود.

البيانات المفاهيمية:

1. الرقم الداخلي.
2. QR Code أو مرجعه.
3. التصنيف.
4. نوع المادة.
5. طبيعة الاستخدام.
6. القيمة الدفترية.
7. الموديل.
8. المنشأ.
9. سنة الصنع.
10. الرقم التسلسلي عند توفره.
11. الجهة المجهزة.
12. رقم الوصل.
13. تاريخ التجهيز.
14. الجهة المالكة أو المسؤولة.
15. الجهة المستلمة الحالية عند وجودها.
16. تاريخ الاستلام.
17. تاريخ دخول الخدمة.
18. الحالة الحالية.
19. رقم مستند الصرف.
20. تسلسل اليومية.
21. تاريخ المستند.

العلاقات:

1. الموجود يرتبط بتصنيف واحد.
2. الموجود يرتبط بنوع مادة واحد.
3. الموجود قد يرتبط بطبيعة استخدام.
4. الموجود يرتبط بجهة مالكة أو مسؤولة.
5. الموجود قد يمتلك سجل تسليم واسترجاع ونقل.
6. الموجود قد يمتلك طلبات صيانة.
7. الموجود قد يمتلك مرفقات.
8. الموجود قد يمتلك سجل شطب واحد إذا شطب.

### VehicleDetails

يمثل البيانات الخاصة بالسيارات.

البيانات المفاهيمية:

1. رقم السيارة.
2. رقم اللوحة.
3. رقم الشاصي.
4. رقم المحرك.
5. قراءة العداد.
6. بيانات السنوية.

العلاقات:

1. يرتبط بموجود واحد من تصنيف سيارات.

### LandDetails

يمثل البيانات الخاصة بالأراضي.

البيانات المفاهيمية:

1. رقم القطعة.
2. المقاطعة.
3. المساحة.
4. العنوان.
5. الملكية.

العلاقات:

1. يرتبط بموجود واحد من تصنيف أراضٍ.

### BuildingDetails

يمثل البيانات الخاصة بالمباني.

البيانات المفاهيمية:

1. المساحة.
2. عدد الطوابق.
3. سنة الإنشاء.
4. حالة المبنى.

العلاقات:

1. يرتبط بموجود واحد من تصنيف مبانٍ.

### Supplier

يمثل الجهة المجهزة سواء كانت موردًا تجاريًا أو جهة حكومية.

البيانات المفاهيمية:

1. اسم الجهة المجهزة.
2. نوع الجهة المجهزة.
3. معلومات التواصل عند توفرها.
4. حالة السجل.

العلاقات:

1. الجهة المجهزة قد ترتبط بعدة موجودات.

### Employee

يمثل الموظف الذي قد يستلم موجودًا.

البيانات المفاهيمية:

1. الاسم.
2. الرقم الوظيفي عند توفره.
3. الجهة.
4. حالة الموظف.

العلاقات:

1. الموظف يرتبط بجهة.
2. الموظف قد يظهر في سجلات تسليم واسترجاع.

ملاحظة: تعتمد النسخة الأولى الإدخال اليدوي للموظفين، ويؤجل الاستيراد من Excel إلى مرحلة لاحقة.

### AssetAssignment

يمثل سجل التسليم والاسترجاع للموجود.

البيانات المفاهيمية:

1. الموجود.
2. الجهة المستلمة.
3. الموظف المستلم عند توفره.
4. تاريخ التسليم.
5. تاريخ الاسترجاع.
6. الحالة عند التسليم.
7. الحالة عند الاسترجاع.
8. الملاحظات.
9. حالة السجل.

العلاقات:

1. السجل يرتبط بموجود واحد.
2. السجل يرتبط بجهة مستلمة.
3. السجل قد يرتبط بموظف مستلم.

### AssetMovement

يمثل نقل الموجود بين الجهات.

البيانات المفاهيمية:

1. الموجود.
2. الجهة المنقول منها.
3. الجهة المنقول إليها.
4. تاريخ طلب النقل.
5. تاريخ اعتماد النقل.
6. حالة الموافقة.
7. ملاحظات النقل.
8. مستند النقل عند توفره.

العلاقات:

1. الحركة ترتبط بموجود واحد.
2. الحركة ترتبط بجهتين.
3. الحركة قد ترتبط بمرفقات.

### MaintenanceRequest

يمثل طلب صيانة لموجود محدد.

البيانات المفاهيمية:

1. الموجود.
2. نوع الصيانة.
3. تاريخ العطل.
4. تاريخ تقديم الطلب.
5. نوع العطل.
6. القائم بالصيانة.
7. الجهة المنفذة.
8. تاريخ إكمال الصيانة.
9. نتيجة الصيانة.
10. تكلفة الصيانة.
11. الملاحظات.
12. حالة الطلب.

العلاقات:

1. طلب الصيانة يرتبط بموجود واحد.
2. طلب الصيانة قد يحتوي مواد مصروفة.
3. طلب الصيانة قد يحتوي مرفقات.

### MaintenanceMaterial

يمثل مادة أو قطعة غيار مصروفة أثناء الصيانة.

البيانات المفاهيمية:

1. طلب الصيانة.
2. اسم المادة.
3. الكمية.
4. سعر الوحدة.
5. التكلفة الإجمالية.
6. المنشأ.

العلاقات:

1. المادة المصروفة ترتبط بطلب صيانة واحد.

قاعدة احتساب:

التكلفة الإجمالية = الكمية × سعر الوحدة.

### MaintenanceSchedule

يمثل إعدادات الصيانة الدورية والتنبيهات.

البيانات المفاهيمية:

1. الموجود أو التصنيف.
2. نوع الدورية.
3. تاريخ آخر صيانة.
4. تاريخ الصيانة القادمة.
5. حالة التنبيه.

العلاقات:

1. الجدولة قد ترتبط بموجود محدد أو بتصنيف.

ملاحظة: تعتمد النسخة الأولى على التاريخ كأساس للاستحقاق.

### AssetWriteOff

يمثل شطب الموجود رسميًا.

البيانات المفاهيمية:

1. الموجود.
2. رقم مستند الشطب.
3. تاريخ مستند الشطب.
4. الجهة المخولة بالموافقة.
5. سبب الشطب.
6. ملاحظات.
7. تاريخ تنفيذ الشطب.

العلاقات:

1. الشطب يرتبط بموجود واحد.
2. الشطب قد يرتبط بمرفقات.

### Attachment

يمثل ملفًا مرفقًا.

البيانات المفاهيمية:

1. اسم الملف.
2. نوع الملف.
3. حجم الملف.
4. نوع السجل المرتبط.
5. معرف السجل المرتبط.
6. تاريخ الرفع.
7. المستخدم الرافع.

العلاقات:

1. المرفق يرتبط بموجود أو صيانة أو نقل أو شطب.

قواعد:

1. الحد الأقصى المبدئي 10MB.
2. الأنواع المدعومة مبدئيًا الصور وPDF.

### AuditLog

يمثل سجل العمليات والتدقيق.

البيانات المفاهيمية:

1. المستخدم المنفذ.
2. نوع العملية.
3. الوحدة المتأثرة.
4. السجل المتأثر.
5. تاريخ ووقت العملية.
6. ملخص العملية.
7. بيانات إضافية عند الحاجة.

العلاقات:

1. يسجل عمليات جميع الوحدات المؤثرة.

## علاقات رئيسية مختصرة

1. `OrganizationUnit` تحتوي عدة `User`.
2. `OrganizationUnit` تحتوي عدة `Asset`.
3. `AssetCategory` يحتوي عدة `AssetType`.
4. `Asset` يرتبط بواحد من `AssetCategory`.
5. `Asset` قد يرتبط بسجل واحد في `VehicleDetails` أو `LandDetails` أو `BuildingDetails` حسب التصنيف.
6. `Asset` يحتوي عدة `AssetAssignment`.
7. `Asset` يحتوي عدة `AssetMovement`.
8. `Asset` يحتوي عدة `MaintenanceRequest`.
9. `MaintenanceRequest` يحتوي عدة `MaintenanceMaterial`.
10. `Asset` قد يحتوي سجلًا واحدًا في `AssetWriteOff`.
11. `Attachment` يرتبط بسجل من الموجود أو العمليات.
12. `AuditLog` يسجل أثر العمليات في الوحدات المختلفة.

## ملاحظات تصميمية مؤجلة

1. هذه الوثيقة لا تحدد أسماء الجداول النهائية.
2. هذه الوثيقة لا تحدد أنواع الحقول أو المفاتيح.
3. هذه الوثيقة لا تحدد فهارس قاعدة البيانات.
4. تصميم قاعدة البيانات التفصيلي يبدأ بعد مراجعة هذا النموذج واعتماده.
