# التصميم التفصيلي للواجهات

هذه الوثيقة تفصل شاشات النظام من حيث الحقول، الإجراءات، التحقق، وحالات العرض. لا تحتوي على كود ولا تمثل تصميمًا بصريًا نهائيًا.

## قواعد عامة لكل الشاشات

1. الواجهة عربية باتجاه RTL.
2. كل شاشة تعرض الأزرار والإجراءات حسب صلاحيات المستخدم.
3. كل جدول يدعم البحث والتصفية والترتيب عند الحاجة.
4. كل عملية حفظ أو اعتماد أو شطب تعرض رسالة نجاح أو خطأ عربية واضحة.
5. لا تظهر بيانات جهة أخرى لمستخدم الجهة.
6. يجب تمييز الحقول الإلزامية بصريًا.
7. لا يسمح بالحذف النهائي للموجودات من أي شاشة.
8. العمليات المؤثرة تسجل في `audit_logs`.

## شاشة تسجيل الدخول

الغرض:

تسجيل دخول المستخدم إلى النظام.

الحقول:

| الحقل | النوع | إلزامي | ملاحظات |
|---|---|---|---|
| اسم الدخول | نص | نعم | يطابق `users.username` |
| كلمة المرور | كلمة مرور | نعم | لا تعرض نصًا |

الإجراءات:

1. دخول.
2. مسح الحقول.

التحقق:

1. لا يسمح بإرسال النموذج إذا كان اسم الدخول أو كلمة المرور فارغًا.
2. عند فشل الدخول تظهر رسالة عربية عامة دون كشف سبب تقني.
3. عند إيقاف المستخدم تظهر رسالة تفيد أن الحساب غير فعال.

## لوحة التحكم

الغرض:

إعطاء ملخص سريع حسب صلاحيات المستخدم.

المؤشرات:

1. إجمالي الموجودات ضمن النطاق.
2. الموجودات حسب الحالة.
3. الموجودات حسب التصنيف.
4. عدد طلبات الصيانة المفتوحة.
5. عدد الصيانات المستحقة.
6. عدد الصيانات المتأخرة.
7. عدد طلبات النقل قيد المراجعة.
8. آخر عمليات سجل العمليات حسب الصلاحية.

الإجراءات:

1. فتح شاشة الموجودات.
2. فتح شاشة الصيانة.
3. فتح شاشة النقل.
4. فتح التقارير.

قواعد العرض:

1. مستخدم الجهة يرى بيانات جهته فقط.
2. المستخدم المركزي يرى الجهات المصرح بها.
3. المدقق يرى المؤشرات للقراءة فقط.

## شاشة قائمة الموجودات

الغرض:

البحث والتصفية والوصول إلى سجلات الموجودات.

أعمدة الجدول:

1. الرقم الداخلي.
2. التصنيف.
3. نوع المادة.
4. الجهة المالكة أو المسؤولة.
5. الجهة أو المستلم الحالي.
6. الحالة.
7. الرقم التسلسلي.
8. تاريخ دخول الخدمة.
9. آخر تحديث.

الفلاتر:

| الفلتر | الوصف |
|---|---|
| بحث عام | الرقم الداخلي، الرقم التسلسلي، النوع، الموديل |
| الجهة | حسب الصلاحية |
| التصنيف | من `asset_categories` |
| نوع المادة | من `asset_types` |
| الحالة | من `asset_statuses` |
| تاريخ دخول الخدمة | من تاريخ إلى تاريخ |
| الرقم التسلسلي غير متوفر | نعم أو لا |

الإجراءات:

1. إضافة موجود.
2. عرض التفاصيل.
3. تعديل.
4. تسليم.
5. استرجاع.
6. طلب نقل.
7. طلب صيانة.
8. شطب.
9. تصدير النتائج.

قواعد الإجراءات:

1. زر الشطب لا يظهر لمن لا يملك صلاحية الشطب.
2. زر النقل لا يظهر للموجود المشطوب.
3. زر الصيانة لا يظهر للموجود المشطوب.
4. زر التسليم لا يظهر إذا كان للموجود تسليم فعال إلا إذا كان الإجراء استرجاعًا.

## شاشة إضافة موجود

الغرض:

إدخال موجود جديد.

أقسام الشاشة:

1. البيانات الأساسية.
2. التصنيف والبيانات المرجعية.
3. بيانات التجهيز.
4. بيانات الاستلام ودخول الخدمة.
5. بيانات خاصة حسب التصنيف.
6. ملاحظات ومرفقات.

حقول البيانات الأساسية:

| الحقل | إلزامي | مصدر البيانات | ملاحظات |
|---|---|---|---|
| الرقم الداخلي | نعم | ينشأ آليًا | وفق `ORG-CAT-YYYY-SEQ` |
| الجهة المالكة أو المسؤولة | نعم | `organization_units` | حسب صلاحية المستخدم |
| التصنيف | نعم | `asset_categories` | يحدد الحقول الخاصة |
| نوع المادة | نعم | `asset_types` | يتغير حسب التصنيف |
| الحالة | نعم | `asset_statuses` | الحالة الأولية |
| طبيعة الاستخدام | لا | `usage_natures` | اختياري |

حقول بيانات الموجود:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| القيمة الدفترية | لا | قيمة ثابتة في النسخة الأولى |
| الموديل | لا | نص |
| المنشأ | لا | نص |
| سنة الصنع | لا | سنة فقط |
| الرقم التسلسلي | لا | يمكن تركه فارغًا إذا تم تحديد أنه غير متوفر |
| الرقم التسلسلي غير متوفر | لا | عند تفعيله لا يلزم الرقم التسلسلي |

حقول التجهيز:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| الجهة المجهزة | لا | من `suppliers` |
| رقم الوصل | لا | نص |
| تاريخ التجهيز | لا | تاريخ |
| رقم مستند الصرف | لا | نص |
| تسلسل اليومية | لا | نص أو رقم |
| تاريخ المستند | لا | تاريخ |

حقول الاستلام:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| تاريخ الاستلام | لا | تاريخ |
| تاريخ دخول الخدمة | لا | تاريخ |
| الجهة المستلمة الحالية | لا | يستخدم عند وجود عهدة مباشرة |
| الموظف المستلم الحالي | لا | يفضل تسجيله عبر عملية تسليم |

التحقق:

1. لا يحفظ الموجود دون جهة وتصنيف ونوع وحالة.
2. لا يسمح بتكرار الرقم الداخلي.
3. إذا لم يدخل الرقم التسلسلي ولم يحدد أنه غير متوفر، تظهر رسالة تنبيه.
4. إذا اختار المستخدم تصنيف سيارات، تظهر حقول السيارة.
5. إذا اختار أراضٍ أو مبانٍ، تظهر حقولها الخاصة.

## شاشة تعديل موجود

الغرض:

تعديل البيانات المسموح بها لموجود مسجل.

قواعد:

1. لا يغير الرقم الداخلي إلا بإجراء تصحيح موثق.
2. لا تعدل حالة مشطوب إلى حالة أخرى في النسخة الأولى.
3. تغيير الحالة المؤثر يتطلب سببًا.
4. كل تعديل يسجل في `audit_logs`.

الإجراءات:

1. حفظ التعديل.
2. إلغاء.
3. عرض سجل التغييرات.

## شاشة تفاصيل الموجود

الغرض:

عرض الملف الكامل للموجود.

الأقسام:

1. ملخص الموجود.
2. QR Code.
3. البيانات العامة.
4. بيانات التصنيف الخاصة.
5. العهدة الحالية.
6. سجل التسليم والاسترجاع.
7. سجل النقل.
8. سجل الصيانة.
9. المواد المصروفة.
10. الشطب إذا وجد.
11. المرفقات.
12. سجل العمليات.

ملخص الموجود:

1. الرقم الداخلي.
2. التصنيف.
3. نوع المادة.
4. الحالة.
5. الجهة المالكة.
6. الجهة أو الموظف المستلم الحالي.

الإجراءات:

1. تعديل.
2. تسليم.
3. استرجاع.
4. نقل.
5. صيانة.
6. شطب.
7. رفع مرفق.
8. طباعة بطاقة موجود.

قواعد العرض:

1. إذا كان الموجود مشطوبًا، تظهر علامة واضحة ولا تظهر إجراءات الحركة والصيانة.
2. إذا لا يوجد رقم تسلسلي، تعرض عبارة "غير متوفر".
3. يظهر سجل الحركة كاملًا ولا يختزل في المستلم الحالي.

## شاشة التسليم

الغرض:

تسجيل تسليم موجود إلى جهة أو موظف.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| الموجود | نعم | يحدد مسبقًا أو عبر بحث |
| الجهة المستلمة | نعم | من `organization_units` |
| الموظف المستلم | لا | من `employees` |
| تاريخ التسليم | نعم | افتراضيًا تاريخ اليوم |
| الحالة عند التسليم | لا | من `asset_statuses` |
| ملاحظات التسليم | لا | نص |

التحقق:

1. لا يسمح بتسليم موجود مشطوب.
2. لا يسمح بتسليم موجود له تسليم فعال.
3. لا يسمح بتسليم موجود خارج صلاحية المستخدم.

## شاشة الاسترجاع

الغرض:

إغلاق عهدة موجود مستلم.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| سجل التسليم الفعال | نعم | يعرض تلقائيًا |
| تاريخ الاسترجاع | نعم | لا يقل عن تاريخ التسليم |
| الحالة عند الاسترجاع | نعم | من `asset_statuses` |
| ملاحظات الاسترجاع | لا | تستخدم للتلف أو النقص |

التحقق:

1. لا يسمح بالاسترجاع إذا لا يوجد تسليم فعال.
2. لا يسمح بتاريخ استرجاع أقدم من تاريخ التسليم.

## شاشة طلب النقل

الغرض:

إنشاء طلب نقل موجود بين الجهات.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| الموجود | نعم | لا يكون مشطوبًا |
| الجهة المنقول منها | نعم | تطابق الجهة الحالية أو المالكة |
| الجهة المنقول إليها | نعم | تختلف عن الجهة المنقول منها |
| سبب النقل | لا | نص |
| ملاحظات | لا | نص |
| مرفقات | لا | PDF أو صور |

حالات الطلب:

1. قيد المراجعة.
2. معتمد.
3. مرفوض.
4. ملغى.

الإجراءات:

1. إنشاء طلب.
2. اعتماد.
3. رفض.
4. إلغاء.

التحقق:

1. لا يسمح بنقل موجود مشطوب.
2. لا يسمح بأن تكون الجهة المنقول إليها نفس الجهة المنقول منها.
3. لا تحدث الجهة الحالية إلا بعد الاعتماد.

الغرض:

عرض وإدارة طلبات الصيانة.

أعمدة الجدول:

1. رقم الطلب.
2. الرقم الداخلي للموجود.
3. التصنيف.
4. الجهة.
5. نوع الصيانة.
6. حالة الطلب.
7. تاريخ الطلب.
8. تاريخ الإكمال.
9. النتيجة.

الفلاتر:

1. الجهة.
2. نوع الصيانة.
3. حالة الطلب.
4. التاريخ.
5. الموجود.

الإجراءات:

1. إنشاء طلب صيانة.
2. عرض التفاصيل.
3. تعديل.
4. إكمال.
5. إضافة مواد مصروفة.

## شاشة إنشاء طلب صيانة

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| الموجود | نعم | لا يكون مشطوبًا |
| نوع الصيانة | نعم | دورية، وقائية، طارئة |
| تاريخ العطل | لا | مطلوب غالبًا للصيانة الطارئة |
| تاريخ تقديم الطلب | نعم | تاريخ |
| نوع العطل | لا | نص |
| القائم بالصيانة | لا | نص أو جهة |
| ملاحظات | لا | نص |

التحقق:

1. لا يسمح بطلب صيانة لموجود مشطوب.
2. تاريخ الطلب إلزامي.
3. نوع الصيانة إلزامي.

## شاشة إكمال الصيانة

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| تاريخ الإكمال | نعم | لا يسبق تاريخ الطلب |
| الجهة المنفذة | لا | نص أو جهة |
| نتيجة الصيانة | نعم | نص أو قائمة لاحقًا |
| تكلفة الصيانة | لا | تكلفة خدمة دون المواد |
| ملاحظات القائم بالصيانة | لا | نص |
| الحالة الجديدة للموجود | لا | حسب نتيجة الصيانة |

التحقق:

1. لا يغلق طلب الصيانة دون نتيجة.
2. لا يقبل تاريخ إكمال أقدم من تاريخ الطلب.
3. عند الإكمال، يمكن تحديث حالة الموجود.

## شاشة المواد المصروفة

الغرض:

تسجيل المواد أو قطع الغيار المستخدمة في الصيانة.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| طلب الصيانة | نعم | محدد مسبقًا |
| اسم المادة | نعم | نص |
| الكمية | نعم | أكبر من صفر |
| سعر الوحدة | نعم | لا يكون سالبًا |
| التكلفة الإجمالية | نعم | تحسب آليًا |
| المنشأ | لا | نص |
| ملاحظات | لا | نص |

التحقق:

1. الكمية أكبر من صفر.
2. سعر الوحدة لا يكون سالبًا.
3. التكلفة الإجمالية = الكمية × سعر الوحدة.

## شاشة الشطب

الغرض:

تنفيذ شطب رسمي للموجود.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| الموجود | نعم | لا يكون مشطوبًا مسبقًا |
| رقم مستند الشطب | نعم | نص |
| تاريخ مستند الشطب | نعم | تاريخ |
| الجهة المخولة | لا | تصبح إلزامية بعد اعتمادها النهائي |
| سبب الشطب | لا | نص |
| ملاحظات | لا | نص |
| مرفق المستند | لا | يفضل إرفاقه عند توفره |

الإجراءات:

1. حفظ كمسودة إذا اعتمدت المؤسسة ذلك.
2. اعتماد الشطب.
3. إلغاء.

التحقق:

1. لا يسمح بشطب موجود مشطوب مسبقًا.
2. رقم وتاريخ المستند إلزاميان.
3. بعد الاعتماد تصبح الحالة مشطوب.
4. بعد الشطب تمنع الحركة والصيانة الجديدة.

## شاشة المرفقات

الغرض:

رفع واستعراض المرفقات.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| الملف | نعم | صورة أو PDF |
| نوع السجل المرتبط | نعم | موجود، صيانة، نقل، شطب |
| ملاحظات | لا | اختياري |

قواعد:

1. الحد الأقصى المبدئي 10MB.
2. لا تعرض مرفقات خارج صلاحية المستخدم.
3. إلغاء المرفقات الخاطئة يحتاج سياسة نهائية.

3. الموجودات حسب الحالة.
4. حركة الموجود.
5. التسليم والاسترجاع.
6. النقل.
7. الصيانة.
8. المواد المصروفة.
9. الشطب.
10. المرفقات.

الفلاتر العامة:

1. الجهة.
2. التصنيف.
3. الحالة.
4. التاريخ من وإلى.
5. نوع المادة.
6. نوع الصيانة عند تقارير الصيانة.

الإجراءات:

1. عرض.
2. تصدير PDF.
3. تصدير Excel.
4. طباعة.

قواعد:

1. التصدير يخضع لصلاحيات المستخدم.

## شاشة المستخدمين

الغرض:

إدارة مستخدمي النظام.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| الاسم الكامل | نعم | نص |
| اسم الدخول | نعم | فريد |
| كلمة المرور | نعم عند الإنشاء | لا تعرض بعد الحفظ |
| الجهة | نعم | من `organization_units` |
| الحالة | نعم | فعال أو موقوف |

الإجراءات:

1. إضافة مستخدم.
2. تعديل مستخدم.
3. إيقاف أو تفعيل مستخدم.
4. إعادة تعيين كلمة المرور.
5. إسناد دور.

## شاشة الأدوار والصلاحيات

الغرض:

إدارة أدوار المستخدمين وصلاحياتهم.

العناصر:

1. قائمة الأدوار.
2. صلاحيات كل دور.
3. نطاق الدور.
4. المستخدمون المرتبطون بالدور.

قواعد:

1. لا يملك أي دور صلاحية حذف موجود نهائيًا.
2. صلاحيات النقل والشطب تعرض بوضوح لأنها عمليات حساسة.

## شاشة الهيكل الإداري

الغرض:

إدارة الجهات ضمن هيكل متعدد المستويات.

الحقول:

| الحقل | إلزامي | ملاحظات |
|---|---|---|
| اسم الجهة | نعم | نص |
| رمز الجهة | نعم | فريد ويستخدم في رقم الموجود |
| نوع الجهة | نعم | حسب الاعتماد النهائي |
| الجهة الأعلى | لا | فارغة للمؤسسة الرئيسية |
| الحالة | نعم | فعالة أو موقوفة |

الإجراءات:

1. إضافة جهة.
2. تعديل جهة.
3. إيقاف جهة.
4. عرض الجهات الفرعية.

قواعد:

1. لا تحذف جهة لديها مستخدمون أو موجودات.
2. إيقاف الجهة لا يلغي تاريخ موجوداتها.

## شاشة البيانات المرجعية

الغرض:

إدارة القوائم التي يعتمد عليها النظام.

القوائم:

1. تصنيفات الموجودات.
2. أنواع المواد.
3. طبيعة الاستخدام.
4. حالات الموجود.
5. أنواع الصيانة.
6. دوريات الصيانة.
7. الجهات المجهزة.

قواعد:

1. لا تحذف قيمة مرجعية مستخدمة في سجلات، بل توقف.
2. رمز التصنيف يجب أن يكون فريدًا.
3. حالات الموجود الحساسة مثل مشطوب لا تعدل إلا بصلاحية عالية.

## شاشة سجل العمليات

الغرض:

تدقيق العمليات المؤثرة.

أعمدة الجدول:

1. التاريخ والوقت.
2. المستخدم.
3. الجهة.
4. نوع العملية.
5. الوحدة.
6. السجل المتأثر.
7. ملخص العملية.

الفلاتر:

1. المستخدم.
2. الجهة.
3. نوع العملية.
4. الوحدة.
5. التاريخ من وإلى.
6. رقم الموجود عند توفره.

قواعد:

1. لا يعدل سجل العمليات.
2. لا يحذف ضمن التشغيل الاعتيادي.
3. يعرض حسب صلاحيات المستخدم.

## حالات الرسائل

رسائل النجاح:

1. تم حفظ الموجود بنجاح.
2. تم تسجيل التسليم بنجاح.
3. تم تسجيل الاسترجاع بنجاح.
4. تم اعتماد النقل بنجاح.
5. تم إكمال الصيانة بنجاح.
6. تم شطب الموجود بنجاح.
7. تم رفع المرفق بنجاح.

رسائل الخطأ:

1. لا يمكن حذف الموجود نهائيًا.
2. لا يمكن تنفيذ العملية لأن الموجود مشطوب.
3. لا يمكن تسليم موجود لديه تسليم فعال.
4. لا يمكن إكمال الصيانة دون نتيجة.
5. حجم المرفق يتجاوز الحد المسموح.
6. نوع الملف غير مدعوم.
7. لا تملك صلاحية تنفيذ هذه العملية.
8. البيانات المدخلة غير مكتملة.

## مخرجات هذه المرحلة

1. تحديد حقول كل شاشة أساسية.
2. تحديد إجراءات كل شاشة.
3. تحديد قواعد التحقق الأولية.
4. تحديد علاقة الشاشات بالصلاحيات.
5. جاهزية للانتقال إلى التصميم التقني أو إنشاء النماذج الأولية للواجهات.
