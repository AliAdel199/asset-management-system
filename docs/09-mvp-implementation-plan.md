# خطة تنفيذ MVP

هذه الوثيقة تحدد خطة تنفيذ النسخة الأولى على مستوى تنظيمي وتحليلي. لا تتضمن كودًا ولا اختيار إطار برمجي نهائي.

## هدف MVP

إطلاق نسخة أولى قابلة للاستخدام الداخلي لإدارة الموجودات الأساسية، حركتها، صيانتها، شطبها، مرفقاتها، وتقاريرها، مع صلاحيات حسب المؤسسة والجهات التابعة.

## مبادئ التنفيذ

1. يبدأ التنفيذ بعد اعتماد وثائق التحليل والتصميم التفصيلي.
2. تبنى الوحدات حسب الاعتماد بينها.
3. يتم اختبار كل وحدة قبل الانتقال إلى التالية.
4. لا يتم استيراد Excel قبل تحليل الملفات وتنظيف البيانات.
5. لا يتم تضمين GPS أو الوقود أو تطبيق الهاتف في MVP.

## المرحلة 1: التحضير التفصيلي

المخرجات:

1. اعتماد نموذج البيانات المفاهيمي.
2. اعتماد سير العمليات.
3. اعتماد مصفوفة الصلاحيات.
4. اعتماد قائمة الشاشات.
5. تثبيت القرارات النهائية المتبقية قدر الإمكان.

معايير الجاهزية:

1. تحديد رموز الجهات والتصنيفات.
2. تحديد الجهات المخولة بالنقل والشطب.
3. تحديد الحد الأدنى النهائي لبيانات الموجود.

## المرحلة 2: الأساس الإداري

الوحدات:

1. الهيكل الإداري.
2. المستخدمون والصلاحيات.
3. البيانات المرجعية.

الهدف:

تجهيز البنية التي تعتمد عليها كل وحدات الموجودات والحركة.

مخرجات المرحلة:

1. تعريف الجهات.
2. تعريف المستخدمين.
3. تعريف الأدوار.
4. تعريف التصنيفات وأنواع المواد والحالات وأنواع الصيانة.

## المرحلة 3: إدارة الموجودات الأساسية

الوحدات:

1. تسجيل الموجودات.
2. تعديل الموجودات.
3. تفاصيل الموجود.
4. QR Code.

الهدف:

تمكين المؤسسة من إنشاء سجل موحد للموجودات.

مخرجات المرحلة:

1. إضافة موجود.
2. رقم داخلي فريد.
3. ربط الموجود بالتصنيف والجهة والحالة.
4. عرض تفاصيل الموجود.
5. منع الحذف النهائي.

## المرحلة 4: بيانات التصنيف الخاصة

الوحدات:

1. بيانات السيارات.
2. بيانات الأراضي.
3. بيانات المباني.

الهدف:

إضافة الحقول الخاصة حسب التصنيف دون تحويل النظام إلى نظام متخصص خارج إدارة الموجودات.

مخرجات المرحلة:

1. حقول السيارات الخاصة.
2. حقول الأراضي الأساسية.
3. حقول المباني الأساسية.

## المرحلة 5: الحركة والعهدة

الوحدات:

1. التسليم.
2. الاسترجاع.
3. النقل بين الجهات.

الهدف:

حفظ تاريخ كامل لحركة الموجود وعدم الاكتفاء بالمستلم الحالي.

مخرجات المرحلة:

1. سجل تسليم واسترجاع.
2. سجل نقل.
3. موافقة مركزية للنقل.
4. عرض تاريخ الحركة في تفاصيل الموجود.

## المرحلة 6: الصيانة والمواد المصروفة

الوحدات:

1. طلبات الصيانة.
2. إكمال الصيانة.
3. المواد وقطع الغيار المصروفة.
4. تنبيهات الصيانة.

الهدف:

متابعة الصيانة والتكاليف والمواد المستخدمة.

مخرجات المرحلة:

1. طلب صيانة مرتبط بموجود.
2. نتيجة صيانة وتكلفة.
3. مواد مصروفة مع احتساب التكلفة الإجمالية.
4. تنبيهات صيانة حسب التاريخ.

## المرحلة 7: الشطب والمرفقات

الوحدات:

1. الشطب.
2. المرفقات.

الهدف:

إدارة الإخراج الرسمي للموجود من الخدمة وربط المستندات بالسجلات.

مخرجات المرحلة:

1. عملية شطب رسمية.
2. رقم وتاريخ مستند الشطب.
3. منع الحركة والصيانة الجديدة للموجود المشطوب.
4. رفع صور وPDF بحد 10MB مبدئيًا.

## المرحلة 8: التقارير وسجل العمليات

الوحدات:

1. التقارير الأساسية.
2. سجل العمليات.

الهدف:

توفير المتابعة الإدارية والتدقيق.

مخرجات المرحلة:

1. تقارير الموجودات حسب الجهة والتصنيف والحالة.
2. تقارير الحركة والصيانة والشطب.
3. تصدير PDF وExcel.
4. سجل عمليات قابل للبحث للمستخدمين المخولين.

## المرحلة 9: الاختبار التشغيلي

أنواع الاختبار:

1. اختبار الصلاحيات.
2. اختبار تسجيل الموجودات.
3. اختبار الحركة والعهدة.
4. اختبار الصيانة والمواد المصروفة.
5. اختبار الشطب.
6. اختبار المرفقات.
7. اختبار التقارير.
8. اختبار سجل العمليات.

معايير القبول:

1. لا يمكن حذف موجود نهائيًا.
2. لا تظهر بيانات خارج صلاحيات المستخدم.
3. يحفظ تاريخ الحركة كاملًا.
4. ترتبط الصيانة بموجود محدد.
5. ترتبط المواد المصروفة بالصيانة.
6. يحسب النظام تكلفة المواد المصروفة.
7. يمنع التعامل التشغيلي مع الموجود المشطوب.
8. تسجل العمليات المؤثرة في سجل التدقيق.

## المرحلة 10: التشغيل التجريبي

النطاق المقترح:

1. جهة أو جهتان من المؤسسة.
2. عينة من الموجودات.
3. عدد محدود من المستخدمين.

الهدف:

اختبار النظام ضمن بيئة عمل حقيقية قبل التعميم.

المخرجات:

1. ملاحظات المستخدمين.
2. قائمة تحسينات ضرورية.
3. معالجة أخطاء التشغيل.
4. قرار الانتقال للتشغيل الرسمي.

## المرحلة 11: التشغيل الرسمي

المتطلبات:

1. نشر النظام على سيرفر المؤسسة.
2. تفعيل HTTPS.
3. تفعيل النسخ الاحتياطي.
4. إنشاء المستخدمين الفعليين.
5. تثبيت الصلاحيات.
6. اعتماد إجراءات الدعم والتشغيل.

## مراحل مؤجلة بعد MVP

1. استيراد الموجودات الحالية من Excel بعد تحليل الملفات.
2. الجرد الإلكتروني المتقدم.
3. تطبيق الهاتف.
4. GPS.
5. إدارة وقود السيارات.
6. احتساب الإهلاك.
7. التكامل مع أنظمة أخرى.

## الاعتمادات الحرجة قبل البرمجة

1. رموز الجهات.
2. رموز التصنيفات.
3. الجهات المخولة بالنقل والشطب.
4. النماذج الرسمية إن وجدت.
5. سياسة المرفقات النهائية إذا اختلفت عن 10MB.
6. صلاحية مستخدم الجهة في إنشاء طلبات الصيانة والنقل.

## مخرجات نهاية هذه المرحلة

1. وثائق تصميم تفصيلي معتمدة.
2. نطاق MVP واضح.
3. تسلسل تنفيذ واضح.
4. نقاط اعتماد نهائية محددة.
5. جاهزية للانتقال إلى تصميم قاعدة البيانات أو تصميم الواجهات التفصيلي.
