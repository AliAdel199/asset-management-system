# سير العمليات

هذه الوثيقة تصف سير العمل المتوقع داخل النظام على مستوى تحليلي. لا تحتوي على كود أو تصميم واجهات نهائي.

## تسجيل موجود جديد

1. يدخل المستخدم المخول إلى وحدة الموجودات.
2. يختار إضافة موجود جديد.
3. يحدد الجهة المالكة أو المسؤولة.
4. يحدد التصنيف ونوع المادة وطبيعة الاستخدام عند توفرها.
5. يدخل الحد الأدنى من البيانات الإلزامية.
6. يدخل البيانات الإضافية مثل القيمة الدفترية، الموديل، المنشأ، سنة الصنع، الرقم التسلسلي، معلومات التجهيز، وتاريخ دخول الخدمة.
7. إذا كان التصنيف سيارات، يدخل بيانات السيارة الخاصة.
8. إذا كان التصنيف أراضٍ أو مبانٍ، يدخل البيانات الأساسية الخاصة بها.
9. ينشئ النظام الرقم الداخلي وفق الصيغة المعتمدة مبدئيًا.
10. يربط النظام QR Code بالموجود.
11. يحفظ النظام السجل.
12. يسجل النظام العملية في `AuditLog`.

نتيجة العملية:

1. موجود مسجل برقم داخلي فريد.
2. حالة أولية واضحة.
3. سجل تدقيق للعملية.

## تعديل بيانات موجود

1. يبحث المستخدم عن الموجود.
2. يفتح صفحة تفاصيل الموجود.
3. يعدل الحقول المسموح بها حسب صلاحياته.
4. يتحقق النظام من عدم تعديل الرقم الداخلي إلا بإجراء مصحح موثق.
5. يحفظ النظام التعديل.
6. يسجل النظام العملية في `AuditLog`.

ملاحظات:

1. لا يسمح بالحذف النهائي.
2. التعديلات المؤثرة يجب أن تظهر في سجل العمليات.

## تسليم موجود

1. يفتح المستخدم المخول سجل الموجود.
2. يختار عملية تسليم.
3. يحدد الجهة المستلمة.
4. يحدد الموظف المستلم عند توفره.
5. يدخل تاريخ التسليم.
6. يدخل ملاحظات عند الحاجة.
7. يتحقق النظام من عدم وجود مستلم حالي فعال لنفس الموجود.
8. يحفظ النظام سجل التسليم في `AssetAssignment`.
9. يحدث النظام الجهة أو المستلم الحالي.
10. يسجل النظام العملية في `AuditLog`.

نتيجة العملية:

1. يظهر المستلم الحالي للموجود.
2. يحفظ تاريخ التسليم ضمن السجل الكامل.

## استرجاع موجود

1. يفتح المستخدم سجل الموجود.
2. يختار عملية استرجاع.
3. يعرض النظام آخر تسليم فعال.
4. يدخل المستخدم تاريخ الاسترجاع.
5. يسجل حالة الموجود عند الاسترجاع.
6. يضيف ملاحظات عند وجود تلف أو نقص.
7. يغلق النظام سجل التسليم الفعال.
8. يحدث النظام حالة الموجود أو موقعه حسب العملية.
9. يسجل النظام العملية في `AuditLog`.

نتيجة العملية:

1. لا يبقى للموجود مستلم فعال.
2. يحفظ تاريخ المستلمين السابقين.

## نقل موجود بين الجهات

1. يفتح المستخدم المخول سجل الموجود.
2. يختار طلب نقل.
3. يحدد الجهة المنقول منها.
4. يحدد الجهة المنقول إليها.
5. يدخل سبب النقل وملاحظاته.
6. ينشئ النظام طلب نقل بحالة انتظار الموافقة.
7. يراجع المستخدم المركزي أو الجهة المخولة الطلب.
8. عند الموافقة، يسجل النظام تاريخ الاعتماد.
9. يحدّث النظام الجهة المرتبطة بالموجود بعد إكمال النقل.
10. يحفظ النظام سجل النقل في `AssetMovement`.
11. يسجل النظام العملية في `AuditLog`.

قواعد مهمة:

1. لا يجوز نقل موجود مشطوب.
2. النقل عملية حركة وليست حالة نهائية للموجود.

## فتح طلب صيانة

1. يفتح المستخدم المخول سجل الموجود.
2. يختار إنشاء طلب صيانة.
3. يحدد نوع الصيانة: دورية، وقائية، أو طارئة.
4. يدخل تاريخ العطل عند وجود عطل.
5. يدخل تاريخ تقديم طلب الصيانة.
6. يحدد نوع العطل والقائم بالصيانة عند توفرهما.
7. يحفظ النظام طلب الصيانة.
8. يمكن تحديث حالة الموجود إلى قيد الصيانة حسب السياسة المعتمدة.
9. يسجل النظام العملية في `AuditLog`.

نتيجة العملية:

1. طلب صيانة مرتبط بموجود محدد.
2. إمكانية إضافة مواد مصروفة ومرفقات لاحقًا.

## إكمال طلب صيانة

1. يفتح المستخدم طلب الصيانة.
2. يدخل تاريخ إكمال الصيانة.
3. يدخل الجهة المنفذة.
4. يدخل نتيجة الصيانة.
5. يدخل تكلفة الصيانة.
6. يضيف ملاحظات القائم بالصيانة.
7. يحدث حالة الموجود حسب النتيجة.
8. يغلق النظام طلب الصيانة.
9. يسجل النظام العملية في `AuditLog`.

## تسجيل مواد مصروفة أثناء الصيانة

1. يفتح المستخدم طلب الصيانة.
2. يختار إضافة مادة مصروفة.
3. يدخل اسم المادة.
4. يدخل الكمية.
5. يدخل سعر الوحدة.
6. يدخل المنشأ عند توفره.
7. يحسب النظام التكلفة الإجمالية.
8. يحفظ النظام المادة ضمن `MaintenanceMaterial`.
9. يسجل النظام العملية في `AuditLog`.

قاعدة احتساب:

التكلفة الإجمالية = الكمية × سعر الوحدة.

## شطب موجود

1. يفتح المستخدم المخول سجل الموجود.
2. يختار عملية شطب.
3. يدخل رقم مستند الشطب.
4. يدخل تاريخ مستند الشطب.
5. يحدد الجهة المخولة بالموافقة عند اعتمادها.
6. يرفق مستند الشطب عند توفره.
7. يضيف سبب الشطب وملاحظاته.
8. يعتمد المستخدم المخول العملية.
9. يغير النظام حالة الموجود إلى مشطوب.
10. يمنع النظام التسليم أو النقل أو الصيانة الجديدة للموجود المشطوب.
11. يسجل النظام العملية في `AuditLog`.

نتيجة العملية:

1. يبقى سجل الموجود محفوظًا.
2. يظهر الموجود في تقارير الشطب.
3. لا يحدث حذف نهائي.

## رفع مرفق

1. يفتح المستخدم السجل المراد إرفاق ملف به.
2. يختار رفع مرفق.
3. يحدد الملف.
4. يتحقق النظام من نوع الملف وحجمه.
5. يحفظ النظام المرفق ويربطه بالسجل.
6. يسجل النظام العملية في `AuditLog`.

قواعد:

1. الأنواع المدعومة مبدئيًا: صور وPDF.
2. الحد الأقصى المبدئي: 10MB لكل مرفق.

## إصدار تقرير

1. يدخل المستخدم إلى وحدة التقارير.
2. يختار نوع التقرير.
3. يحدد معايير التصفية مثل الجهة، التصنيف، الحالة، التاريخ.
4. يعرض النظام النتائج حسب صلاحيات المستخدم.
5. يمكن تصدير التقرير إلى PDF أو Excel.
6. يمكن تسجيل عملية التصدير في `AuditLog` إذا اعتمدت المؤسسة ذلك.

## تنبيهات الصيانة

1. يراجع النظام مواعيد الصيانة القادمة حسب التاريخ.
2. يحدد الصيانة المستحقة.
3. يحدد الصيانة المتأخرة.
4. يعرض التنبيهات للمستخدمين المخولين.
5. عند تنفيذ الصيانة، يحدث النظام موعد الصيانة القادم.

## حالات استثنائية

1. إذا كان الموجود بدون رقم تسلسلي، يسمح بتسجيله برقم داخلي فريد مع تمييز الرقم التسلسلي بأنه غير متوفر.
2. إذا كان الموجود مشطوبًا، تمنع عليه عمليات التسليم والنقل والصيانة الجديدة.
3. إذا كان هناك تعارض بين الحالة الحالية وآخر حركة، يعرض السجل للمراجعة.
4. إذا كانت بيانات Excel غير واضحة، لا يتم الاستيراد حتى تنجز مرحلة تحليل وتنظيف البيانات.
